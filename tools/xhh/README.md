# xhh — 终端刷小黑盒

在终端里纯文本/全屏界面刷小黑盒（xiaoheihe.cn）的热榜、帖子和评论，
界面看起来像普通命令行输出或运维工具。

## 原理

通过 CDP（Chrome DevTools Protocol）连接你**正在运行的日常 Chrome**，
复用小黑盒标签页的登录态读取渲染好的页面。不另起浏览器、不存 Cookie、
不需要登录——你在 Chrome 里登录过一次小黑盒就一直有效
（直到小黑盒自己的过期策略要求重新登录）。

一个常驻守护进程（`xhh_daemon.py`）持有唯一的 CDP 连接，
所有命令通过用户令牌保护的本地 TCP（127.0.0.1:19812）转发给它，
因此 Chrome 的调试确认一天只弹一次。

## 运行

```bash
uv run xhh.py            # 等同 xhh tui
```

或通过启动脚本（Windows，已在 PATH 中）：

```
xhh
```

首次运行 uv 自动解析依赖（websockets / pillow / winsdk / textual）。启动器优先使用
PATH 中的 `uv`，兼容本机旧安装路径；虚拟环境放在 `%LOCALAPPDATA%\xhh\venv`。

## 用法

| 命令 | 说明 |
|---|---|
| `xhh` / `xhh tui` | **TUI 全屏界面（默认）** |
| `xhh browse` | 滚屏浏览模式 |
| `xhh feed [N]` | 单发热榜（默认 20 条，带摘要） |
| `xhh post <id|url> [--art]` | 单发看帖（`--art` 图片用字符画） |
| `xhh stop` | 停止守护进程 |

## TUI 界面教程

裸 `xhh` 进入全屏界面，长得像个日志查看器：

**热榜页**

- `↑` / `↓`：移动选择（支持鼠标点击）
- `回车`：打开选中的帖子
- `0`：刷新热榜（小键盘可达）
- `q`：退出

**帖子页**

- 标题（青色粗体）、作者栏（黄色）、正文、评论区依次排布
- 图片默认折叠成一行 `[图N]`（紫色边框），**回车就地展开**为高分辨率
  盲文点阵图（每字符 2×4 像素、带颜色），再按回车折叠
- 评论按 `#序号` 排列：评论者青色、等级/时间压暗、赞数紫色、
  楼中楼 `↳` 整体压暗
- `b` / `退格` / `q`：返回热榜

**滚屏模式（`xhh browse`）键位**

- 输入编号 + 回车：看帖
- 回车：返回当前热榜（不刷新）
- `0`：刷新热榜
- `q`：退出

## 图片的三种看法

| 方式 | 触发 | 效果 |
|---|---|---|
| OCR 文字提取 | `xhh post` 默认 | 文字为主的图（梗图/截图）直接把图中文字打成文本；判定规则：OCR 字数 ≥ 10 且词数 ≥ 3 |
| 占位链接 | 默认（非文字图） | `[图N]` + OSC8 链接，Ctrl+点击在浏览器看原图 |
| 字符画 | `--art` 或 TUI 展开 | ANSI 真彩半块（post）/ 盲文点阵（TUI） |

## 故障排除

- **帖子打不开，提示人机验证**：小黑盒风控。到 Chrome 的小黑盒标签页
  手动打开任一帖子，完成弹出的验证后重试
- **连不上调试端口 / 守护进程起不来**：Chrome 的 CDP 监听器偶发卡死，
  地址栏输入 `chrome://restart` 重启浏览器（标签页自动恢复）
- **Chrome 没开**：xhh 依赖运行中的 Chrome，先启动浏览器
- **改完代码不生效**：不用管，守护进程有版本自检，下条命令自动换血；
  也可手动 `xhh stop`

## 文件

```
xhh.py            客户端 + 抓取/排版/渲染（OCR、字符画、OSC8 链接）
xhh_daemon.py     常驻守护进程（持有 CDP 连接，令牌保护 127.0.0.1:19812）
xhh_tui.py        TUI 全屏界面（textual，含盲文渲染）
ocr.ps1           Windows OCR（PowerShell 调 WinRT，中文）
xhh.cmd           PATH 入口（uv run 自举）
xhh-terminal.cmd  Tran「打开终端」按钮的入口脚本
pyproject.toml    uv 项目定义（依赖自举）
```

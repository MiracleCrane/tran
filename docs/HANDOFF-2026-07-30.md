## 3. 下一步（按优先级）

### 3.1 【最高】接 kimi 本地 server 的 WebSocket，让待办即时更新

**这是用户反复提的痛点：「待办更新总是不及时，或者一直就不更新了」。**

根因是两层，第一层已修（`45c61b7` 的多会话轮询），第二层是架构性的：
**待办只有模型跑 turn 时才会写**（见 4.5）。

已经查明的可用接口（拆 `@moonshot-ai/kimi-code` 的 bundle 得到，见 4.4）：

| 接口 | 给什么 |
|---|---|
| `GET /sessions/{id}/transcript` | 响应里直接带 **`todos`**——待办真值，零 token |
| `GET /sessions/{id}/transcript/ops?since_seq=N` | 增量 op 流：`todo.upsert` / `task.upsert` / `plan.*`，按 seq 续传。**GET only，不能写** |
| `ws://127.0.0.1:<port>/api/v1/ws` | **推送**。`event.session.work_changed`（带 `busy` 和 `last_turn_reason`）、`status_changed`、`approval.*`、`question.*`、`fs.changed`、`goal.updated`。带 `{seq, epoch}` 水位线和断线重放 |
| `POST /sessions/{id}/prompts::steer` | 往**正在跑的** turn 里插话 |

鉴权：WS 用子协议 `kimi-code.bearer.<token>`，token 来自
`~/.kimi-code/server.token`——`src/main/kimiServerApi.ts` 已经在读了，端口发现
（`~/.kimi-code/server/instances/*.json`）也已经实现，直接复用。

**实施建议**：新建 `src/main/kimiEventStream.ts`，用 Node 22 的全局 `WebSocket`
（**不要加 `ws` 依赖**，见 4.6）。做完之后：

1. 待办/任务读的是真值，不再依赖 ACP 流里恰好出现的 plan 帧
2. 所有会话（含后台）同时被观察，`45c61b7` 的轮询可以退化成兜底
3. `event.session.work_changed` 的 `busy` 转 false 是"turn 结束"的可靠信号

**剩下的硬缺口**：待办内容要真的推进，必须有一次 turn。用户明确说
「不想我来发消息」——意思是 **Tran 自动替他发**，不是"别发"。设计：

- 触发条件：后台任务已收尾 + 待办有未完成项 + 会话空闲（这三个条件
  `PlanCard.tsx` 的 `settledBackgroundTask` 已经在算了）
- 动作：发一条隐藏消息催更新，回显吞掉（Tran 已有隐藏 turn 机制，见

- 门槛必须严：同一个任务只触发一次、只在空闲时、有开关、**并且在界面上标明
  「Tran 自动请求了一次待办更新」**——不能是幽灵行为

## 4. 实测确立的事实（**动手前必读**）

这一节每条都是用真实环境验证过的。**不要凭直觉推翻它们。**

### 4.1 git 的 `--` 分隔符不能一律加

给 `checkout` 加 `--` 会**改坏功能**：`git checkout -- <name>` 的语义是"从索引恢复
该路径的文件"，不是切分支（git 2.43 实测，报 `pathspec 'feature' did not match`）。
`--end-of-options` 对 `branch`/`revert` 有效，对 `checkout` 无效。

所以 `git.ts` 用的是 `assertRef()`——拒绝以 `-` 开头的 ref。
而 `add`/`reset`/`diff` 的 `--` **是安全的**（语义就是"后面全是路径"），已经加了。

只读 git 命令统一加了 `--no-optional-locks`：默认的 `git status` 会顺手**写**索引，
Tran 在旁边轮询就是在和 agent 自己跑的 git 抢 `index.lock`。

### 4.2 Claude Code 的 stream-json 帧（v2.1.220 实测）

一开始有五处猜错了，实测后修正：

- turn 信号是 `system/status` 的 `status:"requesting"`
- `type==='user' && isReplay===true` 的帧**必须丢掉**，否则用户消息重复
- MCP 服务器列表和技能列表在 `system/init` 帧里（还有 `commands_changed`）
- 上下文窗口从 `result.modelUsage.<model>.contextWindow` 取，实测
  claude-sonnet-5 是 **1_000_000**，不是 200k
- `result` 帧**没有** `totalTokens` 字段
- `rate_limit_event` **只给窗口类型和重置时刻，不给已用量/上限**——所以额度环
  对这些窗口显示"无数据"，不编造百分比。这是与 kimi 后端的实质差距

还有一个坑：合成的 `system/plan_usage` 消息**推不到渲染层**——额度环走的是 IPC
拉取（`forge:getPlanUsage`）而不是消息通道。已改成后端留存 + 按后端路由。

### 4.3 两个 permission 枚举不一样，别混

| 位置 | 合法取值 |
|---|---|
| CLI `--permission-mode` | `manual` / `acceptEdits` / `auto` / `bypassPermissions` / `dontAsk` / `plan` —— **没有 `default`** |
| settings.json `permissions.defaultMode` | `default` / `acceptEdits` / `auto` / `bypassPermissions` / `dontAsk` / `plan` —— **没有 `manual`** |

（`claude --help` 与二进制内的枚举表实证。）配置文件的 `default` 等于命令行的
`manual`，都是"每次询问"。Tran 的 `PERMISSION_MODE_MAP` 映射到 `manual`，是对的。

另一条二进制内的原文约束：`"defaultMode": "auto"` **必须写在用户级文件**，
写在项目 `.claude/settings.json` 里会被当作"仓库可控"而**忽略**。

`--print` 非交互模式下**没有交互授权通道**（没观察到 `--permission-prompt-tool`，
也没有权限帧）。所以 Tran 的 Claude 后端靠的是 `--permission-mode` + settings 规则
提前配好，不是弹窗。**交互式 CLI 里则会正常弹窗**，`permissions.ask` 那条路只在
交互模式下有意义。

### 4.4 kimi 本地 server 的能力远超我们用到的

`kimi web --no-open` 起的那个 server（默认端口 58627）除了 `/sessions/{id}/tasks`
还有一大批接口，见 3.1 的表。拆 bundle 的方法：

```bash
npm pack @moonshot-ai/kimi-code   # 或者直接看已安装的
# dist/main.mjs 是打包后的单文件（约 18MB），可读、可 grep
```

### 4.5 待办为什么不会自己更新

```js
TodoModel = defineCheckpointedModel("todo", () => [])
TODO_LIST_REMINDER_TURNS_SINCE_WRITE = 10        // 10 轮没写就提醒模型
TODO_LIST_REMINDER_TURNS_BETWEEN_REMINDERS = 10
```

待办是 checkpointed model，**只有模型调 todo_list 工具时才变**。kimi 自己都知道
模型会忘，所以内置了催更新的提醒机制——而它也是**按 turn 计的**。

`transcript/ops` 是 GET only，所以"绕过模型直接改待办"这条路不通。就算通我也不建议：
伪造 agent 状态，用户很快就不信这个面板了。

会话状态落盘在 `~/.kimi-code/sessions/wd_*/<sessionId>/`：
`agents/main/wire.jsonl` 是 op 日志（`todo.upsert` / `task.upsert` / `context.append_message`），
`state.json` 有 `lastPrompt`。

### 4.6 Node 22 的全局 WebSocket 支持子协议

```
node v22.22.2 / global WebSocket: function / ctor with subprotocol: ok
```

Electron 42 带 Node 22.x，所以**接 WS 不需要加 `ws` 依赖**——而 kimi 的鉴权正好走
子协议（`kimi-code.bearer.<token>`），undici 的 WebSocket 实现虽然不让设自定义
请求头，但子协议是支持的，刚好够用。

### 4.7 便宜模型的实测数据（用户机器，LEVEL_ADVANCED，每型号 5 发热连接）

**端点认任意 model 值**，6 个候选全通。但：

```
kimi-for-coding       min 1515  中位 1813
kimi-k2.6             min 1545  中位 1784
kimi-k2.6-turbo       min 1594  中位 1707
kimi-k2.7-code        min 1656  中位 1693
kimi-k2.7-code-turbo  min 1609  中位 1817
kimi-k3               min 2480  中位 2951
```

**"极速版"没有可测的优势**——除 k3 外全在 1.7~1.8s，差异在噪声里。
（早前单发看到 809ms 是冷启动握手造成的假象。）`outTok` 恒等于 `max_tokens`，
说明每个型号都撞了上限，延迟其实由"生成 N 个 token"决定。
**结论：默认型号维持 `kimi-for-coding`，不折腾。**

额度：`/usages` 的 `limit` 恒为 100——那是**百分比**不是 token 数。31 发（约 2100
token）两个窗口的 `used` 都没动，**只说明低于计数器分辨率，不能解读为不计费**。

指令遵循很差，而且踩了两层：

1. 裸提示词（只在 system 里写"只输出结果、不超过 12 字"）→ 六个型号全部无视，
   一律写 markdown 长文然后被 `max_tokens` 截断
2. 把少样本写成纯文本塞进**单条 user 消息** → **答非所问**：模型把整段当成
   "一堆待处理内容"，抓住**第一个示例**当主题。实际输入
   `npm run build && ...` 得到的是关于 `git status --porcelain` 的表格；
   命名任务里三个不同输入全都回答示例里的"401 排查"

→ 所以 `cheapSummarize()` 用真正的多轮 `user`/`assistant` 轮次 + `stop` 序列 +
输出侧 `terseText()` 清洗，三道防线。**但多轮 + stop 的组合被服务端 400 拒绝，
原因未定**——这就是「提示词自检」按钮要回答的（见 5.2）。

### 4.8 元素类型不能随状态变化（踩过两次）

React 按位置比对元素类型，类型不同即卸载重建。这个仓库踩过两次：

1. 转圈动画被重置——`components` 对象每帧新建，Virtuoso 的 Footer 组件类型不稳定
2. 每轮输出结束整条消息 remount——文本块外面套的 `<Profiler>` 随 `isStreaming`
   出现/消失。代价：思考块的用户折叠态被丢弃（最新块会自己弹回展开）、
   正文 markdown 整树重建 + highlight.js 重跑，正好卡在用户开始读答案那一刻

顺便：`<Profiler>` 的 `onRender` 在生产构建里**根本不回调**（要
`react-dom/profiling` 才生效）。

### 4.9 一个假警报，别再报了

早前把「中文输入法按 Enter 会误发送」报成 P0。**是误判。** CDP 里合成的 Enter

那个分支。用户也确认"用了很久没遇到过"。这是**模式推断，不是验证**。

### 5.2 点一下「提示词自检」

设置页 → 系统 → 总结用型号 → **提示词自检**。打四发（约 400 token），一次只动
一个变量：

```
1 基线：单轮，无 stop          ← 已知可用
2 单轮 + stop                  ← 单独验 stop
3 多轮少样本，无 stop          ← 单独验 assistant 角色消息
4 多轮少样本 + stop            ← 当前失败的组合
```

读法：2 失败 = 端点不支持 `stop`；3 失败 = 不接受 `assistant` 角色消息。
失败行显示**服务端原文**（400 的真实原因只能从那里看）。成功行还显示
`terseText` 清洗后的结果或"清洗后判废"。

### 5.3 检查一下侧栏有没有垃圾会话名

`cleanTitle` 原来只做 `slice(0, 30)`，如果命名请求也返回长文，`ai-titles.json`
里可能存着 `我来分析这个 npm 构建和部署命令：## 命令拆` 这种。已经改成
`terseText` 判废（拿不到干净结果就回退原标题），但**已经存进去的不会自动清**。
需要清的话删 `%APPDATA%/<Tran>/ai-titles.json` 即可（会重新生成）。
